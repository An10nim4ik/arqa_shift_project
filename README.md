# Дневник смен водителя · ARQA

Небольшое веб-приложение для учёта поездок водителя с FastAPI, SQLite и обычным JavaScript (без frontend-сборщика).

## Возможности

- Получение списка поездок за выбранную дату по REST API.
- Сводка: количество, выручка, комиссия, «на руки», наличные/карта.
- Просмотр поездок и переключение дней в браузере.
- Добавление поездки с проверкой входных данных.
- Идемпотентное добавление: одинаковый `id` + те же данные → `200`, новая поездка → `201`, тот же `id` + другие данные → `409`.
- SQLite сохраняет данные между перезапусками сервера.
- Автоматические тесты, включая конкурентную повторную отправку.

## Требования

Python 3.10+.

## Запуск

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Откройте **http://127.0.0.1:8000/**.
Документация и интерактивное тестирование API: **http://127.0.0.1:8000/docs**.

При первом запуске база `data/trips.db` создаётся автоматически, вместе с двумя демонстрационными поездками из `data/sample_trips.json` (01.10.2026). Последующие перезапуски не сбрасывают данные.

Для отдельной базы установите переменную окружения `DB_PATH`, например:

```bash
DB_PATH=/tmp/arqa.db uvicorn app.main:app --reload
```

## Тесты

```bash
pytest -q
```

Проверяются: эталонная сводка (2 поездки, выручка 3900, комиссия 585, на руки 3315, наличные 1500 и карта 2400), валидация, пустые дни, даты, повторные запросы, конфликтующие ID, одновременные повторы и сохранение между перезапусками.

## API

### `GET /api/days/2026-10-01`

```json
{
  "date": "2026-10-01",
  "summary": {
    "trip_count": 2,
    "revenue": 3900,
    "commission": 585,
    "net": 3315,
    "cash": 1500,
    "card": 2400
  },
  "trips": ["...две поездки..."]
}
```

### `POST /api/trips`

```json
{
  "id": "t3",
  "start": "2026-10-02T11:00:00+05:00",
  "end": "2026-10-02T11:20:00+05:00",
  "amount": 2000,
  "payment": "cash",
  "commission": 300
}
```

Ответы:
- `201 Created`: создана новая поездка.
- `200 OK`: повтор запроса с тем же `id` и теми же данными; поездка не дублируется.
- `409 Conflict`: такой `id` уже существует, но полезная нагрузка отличается.
- `422 Unprocessable Entity`: невалидные данные (нулевая или дробная сумма, неверный интервал, отрицательная комиссия, отсутствие часового пояса и т.д.).

## Принятые решения

- **Время:** клиент вводит местное время Казахстана (UTC+5), API требует ISO 8601 с явно указанным смещением. На сервере timestamps хранятся в UTC; для фильтрации определяется местная дата начала поездки в `Asia/Almaty`. Это предотвращает перенос поездок около полуночи в неправильный день.
- **Суммы:** целые тенге, без `float`, чтобы расчёты не теряли точность. `net = revenue - commission`; наличные и карта показывают валовые суммы поездок.
- **Идемпотентность:** `id` — уникальный идентификатор поездки от клиента. Уникальность обеспечивает `PRIMARY KEY` в SQLite и атомарная вставка `ON CONFLICT(id) DO NOTHING`, а не проверка до вставки.
- **Невалидные данные:** `amount > 0`, `0 <= commission <= amount`, `end > start`, валидный способ оплаты `cash/card`; лишние поля запрещены.
- **Простота:** API, HTML, CSS, JS и SQLite без дополнительных сервисов, чтобы проверяющий мог запустить всё одной командой.

## Ограничения и возможные улучшения

Это тестовое приложение, а не законченный банковский/таксопарковый backend. Для production понадобятся авторизация, привязка поездок к водителю, HTTPS, миграции схемы, мониторинг, контроль доступа и отдельная БД при росте нагрузки. Для денежного учёта в нескольких валютах нужен отдельный формат сумм/валют. Здесь смена определяется **местной датой начала поездки**, потому что в задании явно не определены ночные смены, пересекающие календарные сутки.

## Использование ИИ

ИИ помог подготовить каркас FastAPI, веб-интерфейс, тестовые сценарии и документацию. Решения по идемпотентности, часовому поясу, ограничениям суммы/комиссии и обработке ошибок проверялись отдельно. Тесты используются для проверки сгенерированного кода, а не для безусловного доверия к нему.
